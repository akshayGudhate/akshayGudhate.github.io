System Architecture: Bitamin

Bitamin is a distributed platform designed to handle real-time messaging, campaign orchestration, and workflow automation across multiple external channels.

The system is structured as a set of loosely coupled components connected through an event-driven backbone.

  • Ingress Layer: Handles webhook ingestion from external platforms with validation and normalization
  • Messaging Layer: NATS-based pub/sub system enabling asynchronous, decoupled communication
  • Processing Layer: Worker services responsible for business logic execution and state transitions
  • Workflow Engine: Executes multi-step automation pipelines (triggers → conditions → actions)
  • Integration Layer: Isolated connectors for third-party systems (Zoho, IndiaMART, Razorpay)
  • Storage Layer: PostgreSQL for transactional consistency, Redis for caching and ephemeral state

Request Flow

Webhook → Ingestion Service → NATS Topic → Worker → Workflow Engine → Action (Message / API Call)

This model allows ingestion, processing, and execution to scale independently, while maintaining clear separation of concerns across the system.

Key Engineering Decisions

  • Migration: RabbitMQ → NATS
    Shifted to NATS to reduce broker complexity, minimize latency, and simplify routing topology. Prioritized operational simplicity and real-time responsiveness over feature-heavy messaging patterns.
  • Migration: Node.js → Golang
    Rebuilt critical services in Go to better handle concurrency and high-throughput workloads, reducing resource overhead and improving system predictability under load.
  • Event-Driven Architecture
    Adopted event-based communication to decouple ingestion, processing, and workflow execution, allowing independent scaling and failure isolation.
  • gRPC for Internal Communication
    Introduced gRPC for service-to-service calls to reduce latency and enforce stricter interface contracts.
  • Integration Isolation
    Designed integration layer to prevent third-party failures from impacting core messaging workflows.
